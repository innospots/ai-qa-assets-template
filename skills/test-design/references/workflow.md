# TDS 分步生成工作流

本文件定义 `test:design` 的**任务拆解、逐份生成、逐份审查**流程。与 [`SKILL.md`](../SKILL.md) 配合使用。

## 0. 编排前置（Superpowers）

**必须先**读取并遵循 **`using-superpowers`**（Superpowers 插件 Skill，`/using-superpowers`）。

然后按 using-superpowers 的规则：

1. 确认本任务适用 `test:design`（已读 `references/tds-spec.md` 与 `examples/` 样例）。
2. 将后续步骤拆成**独立任务**，为每项创建 todo（或等价任务清单）。
3. **一次只处理一个任务**：生成 → 审查 → 标记完成 → 再进入下一任务。
4. 禁止在未审查前批量落盘多份文档。

若当前环境无法加载 Superpowers 插件，仍必须遵守上述「单任务生成 + 单任务审查」节奏，并在交付中说明未调用插件。

## 1. 输入盘点（任务 T0）

### 1.1 引导式输入（可选）

无完整 PRD/PDD 或用户要求引导时，**先**走 [`guided-intake.md`](guided-intake.md)（AskQuestion Phase 1–6），产出 intake 摘要；**确认后**再执行下方文档盘点。引导阶段不落盘 TDS。

有完整文档且无需引导 → 跳过 §1.1。

### 1.2 文档与存量盘点

开始前收集并记录：

| 输入 | 别名 | 用途 |
| --- | --- | --- |
| 产品需求文档（PRD） | 需求文档、需求说明 | 范围、验收标准、业务规则 |
| 产品设计文档（PDD） | 产品功能文档、功能说明、交互说明 | 流程、状态、异常、平台差异 |
| 已有 TDS | `designs/` 存量 | 变更、对齐、避免重复 |
| 接口/数据契约 | API 文档 | 字段、权限（视需要） |

**要求：**

- 用户提供的文档路径、附件或粘贴内容优先；仓库内路径写入 Front Matter `sources`。
- PRD 与 PDD/产品功能文档冲突时：**停止扩范围**，写入「待确认问题」，不自行裁决。
- 缺失且影响范围/风险判断的输入 → 「待确认问题」，不得猜测补全业务规则。

**T0 产出（写入任务清单，不直接写 TDS）：**

- 目标 `{domain}`、模块边界
- 场景列表（业务动作 → `{scene}.design.md`）
- 模块级 vs 场景级待确认问题初稿
- 是否仅对齐存量、或新建/增量

## 2. 任务拆解模板

按模块一次性规划，按任务逐次执行：

| 任务 ID | 内容 | 产出 |
| --- | --- | --- |
| T0 | 输入盘点与场景规划 | 任务清单 + 待确认问题 |
| T1 | 模块 Index | `designs/{domain}/index.md` |
| T2…Tn | 场景 TDS（**每场景一项**） | `designs/{domain}/{scene}.design.md` |
| T_review-1… | 逐份规范审查 | 修正后的对应文件 |

规则：

- **T1 必须先于** T2…Tn 完成并通过审查。
- 每个场景单独一项任务；禁止在一个任务里同时写 Index + 多个场景。
- 存量对齐时，可先 T_review 盘点，再按文件拆 T1、T2…。

## 3. 单任务生成（T1 / T2…Tn）

每个生成任务只做一个文件：

1. 标记任务 `in_progress`。
2. 重读 [`tds-spec.md`](tds-spec.md) 对应章节 + 对应 `examples/` 样例。
3. 只写当前任务目标文件；引用 Index，不复制公共规则。
4. Front Matter：`status: draft`（新建）或按变更递增 `version`。
5. 写完后**立即**进入该文件的审查任务，通过后再 `completed`。

## 4. 单任务审查（T_review-*）

对刚生成的**那一个**文件，打开 [`review-checklist.md`](review-checklist.md) 逐项核对：

1. 结构、Front Matter、ID、`DS-` 清单、边界值、写作边界。
2. 发现问题：**在本任务内修正**，再次过清单，直到通过。
3. 记录：审查项、发现的问题、已修正项（交付时汇总）。

禁止：审查未通过就启动下一份文档的生成任务。

## 5. 模块收尾

全部 TDS 任务与审查通过后：

1. 用 [`review-checklist.md`](review-checklist.md)「模块级收尾」再过一遍。
2. 更新 `designs/{domain}/` 相关 README（若存在且需要导航）。
3. 交付摘要：
   - 输入文档与 `sources` 映射
   - 已完成任务列表
   - `DS-` 清单与暂缓项
   - 审查中发现并已修正的问题类型
   - 是否建议 `test:case`（仅提示，不自动改 Case）

## 6. 存量对齐任务

用户要求调整已有模块时，在 T0 增加**差距清单**，再拆任务：

| 差距类型 | 任务方式 |
| --- | --- |
| Index 缺/旧结构 | 单独 T1 |
| 每个场景结构不符 | 每文件一项 T2…Tn |
| 公共规则重复 | 上收 Index 后再改场景 |

对齐时遵循 [`tds-spec.md` 第 12 节](tds-spec.md#12-修改与评审)；**保留已发布 `DS-` 编号与意图**。
