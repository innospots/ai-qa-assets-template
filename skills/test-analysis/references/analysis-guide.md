# 失败分析指南

先报告事实，再提出推断；证据不足不得直接改资产。

## 分析步骤

1. 确认 Case ID、平台、设备、命令、失败步骤与时间
2. 对照 Case 预期与 Flow 断言；检查 Module、`${output...}`、平台选择器
3. 结合日志、截图、报告复现链路；区分首因与连锁失败
4. 分类：`Product` | `Case` | `Flow` | `Module` | `Data` | `Environment` | `Unknown`
5. 输出：实际/预期、证据、置信度、建议负责人、最小复验命令

## 限制

- 不凭单张截图断言产品根因
- 不为通过而降低预期、删断言、改 Case
- 用户只要求分析时不实施修复
- 日志中密码、Token、Cookie、个人信息须脱敏
