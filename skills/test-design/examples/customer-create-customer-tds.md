# 创建客户测试设计

> 本文档继承 [客户管理测试设计](./../examples/customer-index.md) 中的公共角色、公共业务规则和公共测试要求。

## 1. 场景说明

管理员或具有创建权限的运营人员，通过客户管理创建新客户。创建成功后，该客户可在当前租户内被查询和使用。

## 2. 场景目标

验证：

1. 合法数据能够创建成功
2. 非法数据不能创建
3. 客户编号唯一性生效
4. 未授权用户不能创建
5. 重复提交不产生重复客户
6. 创建后的数据正确保存，且初始状态为正常

## 3. 前置条件

除模块公共前置条件外，需要：

- 当前用户具有客户创建权限（正向场景）
- 拟使用的客户编号在当前平台内尚不存在（正向场景）

## 4. 输入与输出

| 类型 | 内容 |
| --- | --- |
| 输入 | 客户名称、客户编号、手机号（可选） |
| 操作 | 提交创建客户 |
| 输出 | 创建成功或业务错误 |
| 数据变化 | 新增一条属于当前租户的客户记录 |
| 后续影响 | 客户可被查询、使用；编号此后不可改 |

## 5. 场景业务规则

继承模块公共业务规则。另外：

1. 创建成功后初始状态为「正常」
2. 必须记录创建人和创建时间
3. 相同业务请求不得创建出第二条客户

## 6. 基本业务流程

```text
进入客户管理
    ↓
发起新增客户
    ↓
填写客户资料
    ↓
提交
    ↓
参数校验
    ↓
业务规则校验
    ↓
保存客户
    ↓
创建成功
```

## 7. 测试设计

### 7.1 正常场景

- 全部合法字段创建
- 只填必填字段创建（可选手机号为空）

同构路径不拆多条正向 `DS-`；中英文名称差异放入数据要求。

### 7.2 异常场景

- 客户名称为空
- 客户编号为空
- 客户编号已存在
- 手机号格式非法

### 7.3 边界场景

客户名称：

- 1 个字符：允许
- 100 个字符：允许
- 101 个字符：拒绝
- 纯空格：拒绝（去空格后为空）

客户编号：

- 1 个字符：允许
- 32 个字符：允许
- 33 个字符：拒绝

### 7.4 数据场景

客户名称按规则覆盖：中文、英文、中英数字组合、前后空格（保存后应被去除）。Emoji、换行是否允许以产品规则为准；未确认前不扩展为独立 `DS-`。

### 7.5 权限场景

- 管理员创建：允许
- 运营人员创建：允许
- 查看人员创建：拒绝（界面不可用，接口同样拒绝）
- 其他租户身份向当前租户写入：拒绝

权限不只检查入口是否展示，还要检查接口与是否落库。

### 7.6 状态场景

创建不涉及已有客户的状态转换。只验证：成功记录的初始状态为「正常」，而不是停用或空状态。

### 7.7 重复操作与幂等

- 短时间内连续提交同一份合法资料
- 第一次请求超时后用相同编号再次提交

检查：最多一条客户记录；错误时可识别，可再次发起且结果可判定。

### 7.8 数据一致性

创建成功后应同时满足：

- 列表可查到
- 详情字段正确
- 接口返回与提交一致（名称已去前后空格）
- 持久化属于当前租户
- 创建人、创建时间有值
- 有对应操作日志

### 7.9 异常恢复

- 请求超时、依赖服务失败、保存失败时：不留下不完整记录，不产生重复编号占用不明的数据，返回明确错误，允许重新提交。
- 此类验证标为专项，不纳入默认可自动化范围。

### 7.10 风险与优先级

| 风险 ID | 风险描述 | 影响 | 可能性 | 优先级 | 对应场景 |
| --- | --- | --- | --- | --- | --- |
| R-01 | 编号重复仍写入 | 高 | 中 | P0 | DS-CUSTOMER-CREATE-103 |
| R-02 | 无权限用户经接口创建成功 | 高 | 中 | P0 | DS-CUSTOMER-CREATE-105 |
| R-03 | 重复提交产生两条客户 | 高 | 中 | P0 | DS-CUSTOMER-CREATE-106 |
| R-04 | 成功后列表与持久化不一致 | 高 | 低 | P0 | DS-CUSTOMER-CREATE-001 |

### 7.11 平台差异

| 场景 | Android | iOS | Web | 差异说明 |
| --- | --- | --- | --- | --- |
| DS-CUSTOMER-CREATE-001 | 适用 | 适用 | 适用 | 规则一致，交互入口可以不同 |
| DS-CUSTOMER-CREATE-105 | 适用 | 适用 | 适用 | 三端都必须验证接口拒绝 |

## 8. 测试数据要求

| 数据 | 要求 |
| --- | --- |
| 完整合法客户 | 名称、编号、合法手机号均符合规则且编号未占用 |
| 仅必填客户 | 名称与编号合法，手机号空 |
| 已存在编号 | 编号与库中已有客户相同 |
| 超长名称 | 名称恰好 101 字符 |
| 边界名称 | 1 字符、100 字符 |
| 无权限用户 | `users.viewer` |
| 其他租户 | `tenants.other` |

## 10. 假设与约束

- **假设**：错误提示存在且调用方可区分校验失败与系统失败；创建时间精度到秒即可。
- **约束**：本文件是格式示例，不对应仓库内真实客户功能。
